# Publishing Guide

This guide explains how to automatically publish Markdown Printer to Chrome Web Store, Firefox Add-ons, and Edge Add-ons using GitHub Actions.

## How It Works

The workflow (`publish.yml`) automatically:

1. Checks the current published version on each store
2. Compares it with your local manifest version
3. **Only publishes to stores where the version is outdated**
4. Skips stores that are already up-to-date

This prevents unnecessary submissions and review delays!

## Setup

### 1. Install publish-browser-extension

```bash
pnpm add -D publish-browser-extension
```

### 2. Configure GitHub Secrets

Add these secrets to your repository at `Settings > Secrets and variables > Actions > Repository secrets`:

#### Chrome Web Store

The workflow uses Chrome Web Store API v2, which authenticates as a service account (API v1.1 and its OAuth refresh tokens stopped working on 2026-10-15). See [Google's guide](https://developer.chrome.com/docs/webstore/service-accounts).

1. In [Google Cloud Console](https://console.cloud.google.com/), select a project and enable the **Chrome Web Store API**
2. Under **IAM & Admin > Service Accounts**, create a service account (no roles needed)
3. On the service account's **Keys** tab, add a JSON key and download it
4. In the [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole), open **Publisher > Settings** and add the service account's email (one service account per publisher)
5. Add to GitHub:
   - Secret `CHROME_SERVICE_ACCOUNT_KEY`: the entire contents of the JSON key file
   - Variable `CHROME_PUBLISHER_ID`: the ID in the dashboard URL, `https://chrome.google.com/webstore/devconsole/<publisher-id>`

#### Firefox Add-ons

1. Log in to [addons.mozilla.org](https://addons.mozilla.org/)
2. Go to **Tools > Manage API Keys**
3. Generate credentials:
   - `FIREFOX_ISSUER`
   - `FIREFOX_SECRET`

#### Microsoft Edge Add-ons

1. Sign in to [Partner Center](https://partner.microsoft.com/)
2. Visit the [Publish API page](https://partner.microsoft.com/en-us/dashboard/microsoftedge/publishapi)
3. Click **Create API credentials**:
   - `EDGE_PRODUCT_ID` (from your extension overview page)
   - `EDGE_CLIENT_ID`
   - `EDGE_API_KEY`

## Usage

### Option 1: Manual Trigger

1. Go to `Actions` tab in GitHub
2. Select `Publish Extensions` workflow
3. Click `Run workflow`

The workflow will check all stores and only publish where needed.

### Option 2: Automatic on Tag

Create and push a version tag:

```bash
git tag v1.0.4
git push origin v1.0.4
```

The workflow will automatically run and publish to outdated stores.

## Version Management

### Update versions across all manifests

```bash
# Update version in package.json (the only place — extension manifests
# are regenerated by build.js from package.json).
npm version patch  # or minor, or major

# Build and commit
pnpm run build
git add .
git commit -m "Bump version to 1.0.4"
git tag v1.0.4
git push origin main --tags
```

## Workflow Output

The workflow provides a summary showing which stores were published to:

```
Publication Summary
- Chrome: ✓ Published
- Firefox: ⊘ Skipped (up to date)
- Edge: ⊘ Skipped (up to date)
```

## Important Notes

### Auto-Submit Behavior

- **Chrome**: uploads are submitted for review automatically.
- **Edge**: uploads are submitted for review automatically. If a previous version is still under review, Edge rejects the submission and the Edge step fails (Chrome and Firefox still publish); re-run the workflow once the review clears, or submit the uploaded draft in the [Edge Partner Center](https://partner.microsoft.com/en-us/dashboard/microsoftedge/overview).
- **Firefox**: automatically submits for review (cannot be skipped).

**Note for Chrome:** if a previous version is still under review when the workflow runs, the publish step will fail with "Item already in review". Wait for the pending review to clear before tagging a new version.

## Troubleshooting

### Chrome: "Token exchange failed" or 403 from the version check

Check that `CHROME_SERVICE_ACCOUNT_KEY` holds the full JSON key file, the Chrome Web Store API is enabled in that key's project, the service account's email is added under **Publisher > Settings** in the Developer Dashboard, and `CHROME_PUBLISHER_ID` matches the dashboard URL.

### Chrome/Edge: "Item already in review"

A version is currently under review. Wait for review completion before tagging a new version. (Chrome and Edge auto-submit, so this can happen on rapid successive releases.)

### Firefox: "Submission failed"

Ensure you've zipped the source code correctly and that your extension follows AMO guidelines.

### Edge: "Authentication failed"

Verify your Product ID is correct by checking your extension's overview page in Partner Center.

### Version check fails

If a store's version check or publish step fails, that store is marked failed in the summary and the job fails, but the other stores still publish. Check the logs for details, then re-run the workflow from the Actions tab; stores that already have the version are skipped.

## Manual Publishing

If you prefer to publish manually, you can use the CLI directly:

```bash
# Publish to specific stores
npx publish-browser-extension \
  --chrome-api-version v2 \
  --chrome-zip dist/chrome.zip \
  --chrome-extension-id pfplfifdaaaalkefgnknfgoiabegcbmf \
  --chrome-publisher-id "$CHROME_PUBLISHER_ID" \
  --chrome-service-account-client-email "$CHROME_SERVICE_ACCOUNT_CLIENT_EMAIL" \
  --chrome-service-account-private-key "$CHROME_SERVICE_ACCOUNT_PRIVATE_KEY"
```

## Notes

- First-time submissions must be done manually through each store's dashboard
- The workflow assumes you're using the same version for Chrome and Edge (both use extension-chrome)
- Source code is automatically zipped for Firefox submissions
- All submissions go through each store's review process before being published
