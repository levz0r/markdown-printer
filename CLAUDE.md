# Claude Code Reminders

## Pre-Commit Checklist

**ALWAYS run before committing:**

1. **Format files**: `pnpm run format`
2. **Run tests**: `pnpm run test`
3. **Check linting**: `pnpm run lint`

## Git Workflow

- Always format before committing
- Ensure all tests pass
- Verify no linting errors

## Version Bump Checklist

**ALWAYS do these before bumping version:**

1. **Add an entry at the top of `CHANGELOG.md`** for the new version.
   The four `description-*.md` files (en/fr/he/hi) hold only marketing
   copy now and link out to CHANGELOG.md — leave them alone unless the
   marketing copy itself is changing.

2. **Bump version** in `package.json` only.
   The Chrome and Firefox manifests are generated by `build.js` from
   `package.json`, so no manual edits are needed (and `extension-chrome/`
   and `extension-firefox/` are gitignored).

3. **Run pre-commit checks**: format, test, lint

4. **Commit and push to develop**

5. **Merge to main** to trigger auto-tag and publish

## After Publishing

The per-store "Detailed description" fields are **not** auto-synced.
If the marketing copy in any `description-*.md` changed, paste the new
text into the corresponding store dashboards:

- **Chrome Web Store** Developer Dashboard → Store listing → Detailed description
- **Edge Add-ons** Partner Center → Listings → en/fr/he/hi → Detailed description
- **Firefox Add-ons** AMO → Manage Versions → Add-on description (per locale)

If only `CHANGELOG.md` changed, no store-listing update is needed —
users follow the "Version history" link from the listing.

## Common Commands

```bash
# Format all files
pnpm run format

# Run tests
pnpm run test

# Run linter
pnpm run lint

# Build extensions
pnpm run build
```
